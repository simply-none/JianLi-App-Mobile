# 渐离App 移动端开发技能（jianli-mobile-app）

## 这是什么
封装「渐离App 移动端」的架构约定、数据层对齐规则、加密复刻、双端同步协议、构建环境与逐功能域知识，让 AGENTS 在本工程里按既定模式开发、维护、扩展功能，并避开已知雷区。它不是运行时功能，而是「开发该工程的知识库」。

- 桌面端契约（db.sqlite 表结构、vault 加密 `crypto.ts`、同步对端 `syncModule.ts`）以桌面技能为准：`C:\cod\jianli\jianli-app\.workbuddy\skills\jianli-app\SKILL.md`

## 全局红线（先读，违反必踩雷）
1. 【环境雷区·中文用户名】跑任何 dart / flutter / gradle 命令前必须设置 ASCII 临时目录：`export TMP=C:\src\tmp TEMP=C:\src\tmp`（Windows 用户目录含中文 `C:\Users\风起`，Dart build_runner 自举编译会因 %TEMP% 含中文失败：`Unable to read program.dill`）。Gradle 再遇编码问题优先怀疑路径。
2. 【构建镜像】构建 shell 里的 `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`、`PUB_HOSTED_URL=https://pub.flutter-io.cn` 必须是**当前有效值**——旧会话继承 cernet 旧镜像变量会导致 flutter_embedding_debug 等构件拉取失败。Gradle/Maven 已配阿里云镜像（`android/settings.gradle.kts`），勿删。
3. 【drift 三大铁律】写/改表定义前必读下方「数据层（drift）」，违反会导致整库解析失败、生成空壳 .g.dart 或列名与桌面端错位。
4. 【加密对齐】vault 信封格式必须与桌面端 `electron/main/module/vault/crypto.ts` 逐字节一致（AES-256-GCM + PBKDF2 iter=200000，JSON 信封 `{v,kdf,iter,salt,iv,ct}` 全 b64）。改加密相关代码前先读「加密（vault 复刻）」一节。
5. 【sqlite3 hooks】`pubspec.yaml` 里的 `hooks.user_defines.sqlite3`（Windows 用系统 `winsqlite3.dll`、Android 用裸名 `sqlite3` + jniLibs 手动分发 .so）是踩坑后固化的配置，**严禁删除或改回默认**（默认 hook 从 GitHub 下载 dll 国内超时；`name_android` 填 `libsqlite3.so` 会被再装饰成 `liblibsqlite3.so.so` 崩溃）。
6. 【UI 约定·forui】全 App UI 组件用 **forui（shadcn 风格）**，详见下方「UI 体系（forui）」。三条铁律：① Material 导入统一用 `package:material_ui/material_ui.dart`（**严禁与 `flutter/material.dart` 混用**——两套平行 Material 类，混用会断 Theme 继承链、ThemeData 类型不兼容）；② 严禁硬编码颜色，取色一律 `context.theme.colors.*`，字体一律 `context.theme.typography.body.*`；③ feature-first 原子拆分，单文件职责单一，每个功能/组件带中文注释。
7. 【同步白名单】新增可同步表**默认 TEXT 主键**（INTEGER 主键表需双端 pk 适配，先例见「主题对话」小节），且同时改两端白名单：移动端 `lib/core/sync/sync_service.dart` 的 `kSyncableTables` + 桌面端 `electron/main/module/sync/syncModule.ts` 的 `SYNCABLE_TABLES` 与 `tablePk()`（PC UI 另有 `src/store/useSync.ts` 的 `SYNC_TABLES`；改桌面端需重启 Electron）。幂等写只有 `INSERT OR REPLACE`（移动端）/ `ON CONFLICT(pk) DO UPDATE`（桌面端 newSql upsert），传输当前为明文 JSON（仅限受信局域网，会话加密是 P3 TODO）。
8. 【文档同步】每次大改动后同步更新**对应模块**（功能域状态改 `modules/features.md`、雷区/约定改对应主题模块），并在 `modules/changelog.md` 追加一条日期前缀记录；发现文档与代码不符，直接修正文档。
9. 【**弹窗（底部抽屉）高度三档 + 键盘处理分档（2026-09-12 重定，全局强制）**】完整规格见 `modules/interaction-patterns.md` §一，要点：
   ① **只有三档**：`SheetSize.sm / md / lg` = **30% / 50% / 80%**，**禁止第四种**，新增弹窗必须挂档（不要在调用点写裸比例）；比例值 = `AppTokens.sheetHeightSm/Md/Lg`。
   ② **键盘处理分档**：
      - **lg（详情 / 新增 / 编辑 / 长表单 / **一切含输入框的弹窗**）**：高度 = **屏幕高 × 0.8**，取自 `sheetMaxHeightFull(context, size)`（`lib/app/ui/sheet_surface.dart`），**不扣键盘**；调用点必须配对 `mainAxisMaxRatio: AppTokens.sheetHeightLg` + `resizeToAvoidBottomInset: false`（forui 默认 `mainAxisMaxRatio: 9/16≈56%` 会压住 80%、默认 `resizeToAvoidBottomInset: true` 会让键盘一弹抽屉就折叠收缩）；内部承载件**必须定高**（`BoxConstraints.tightFor(height: maxH)` 或 `SizedBox(height:)`），**绝不能只用 `ConstrainedBox(maxHeight:)`**——那只是上界，内容少会 hug，抽屉缩到 ~30% 够不到 80%（Request 5 实踩）。⚠️ **2026-09-13 用户定案：判定标准看「内含输入框」而非「表单长短」——只要抽屉里有 TextField/FTextField/SheetInputBox/SheetMultilineBox，一律 lg 80vh**（原「输入」曾归 sm/md，实测键盘一弹抽屉被压/折叠，已全部改 lg）。
      - **sm / md（确认 / 单选 / 多选 / 日期——**不含输入框**）**：高度 = **（屏幕高 − 键盘高）× 档位**，取自 `sheetMaxHeight(context, size)`，**必须扣键盘**；forui `ShiftedSheet` 用 `dy = max(0, H − 抽屉高 − 键盘高)` 摆放，抽屉高一旦超过「H − 键盘高」`dy` 被夹到 0 不再上移，抽屉被键盘盖住、底部按钮点不到。
   ③ 抽屉**定高**（lg 用 `tightFor` / 待办 `_sheetScaffold` 用 `SizedBox`），内容超出由**中间滚动区**承担；**画布 09/10 是 `hug_contents` 唯一例外**（用 `maxHeight` 上限）。
   ④ 弹窗标题一律 `sheetTitleStyle(context)` = **17/Bold**（画布 09/10 规格），**弹窗内任何字段的字号都不得大于它**；**条目标题（详情标题、编辑标题输入框）用 15/Bold**，比弹窗标题小 2 号，详情与编辑必须一致；⚠️ **别用裸 `typography.body.lg` 当标题**（主题按 `baseFontSizeNormal` 缩放后 body.lg ≈ 13.7，比正文还小）。
   ⑤ ⚠️ 旧结论「键盘弹起时整张抽屉抬到键盘上方」是错的（`mainAxisMaxRatio: null` 时期），已修正：lg 明确「覆盖不重排」、sm/md 按可用高度收缩。
   ⑥ ⚠️ **嵌套抽屉（从抽屉 A 内再开抽屉 B）不是崩溃原因**——传 `mainAxisMaxRatio` + `resizeToAvoidBottomInset: false` 本身**可以嵌套**，已验证先例 `note_sheets.dart`（标签管理 lg 抽屉内再开「标签颜色」sm / 「标签编辑」lg / `showSheetConfirm` 删除确认，参数与父级同款，工作正常）。2026-09-13 XLII 报的「嵌套抽屉崩溃」实为**轮式 picker（`FTimePicker`/`FDateTimePicker`）主轴无界**（`SheetScaffold` body 在 `SingleChildScrollView` 内无界）→ 必须给 picker 显式套 `SizedBox(h160/h200)` 定高；`datetime_pickers.dart` 注释里「嵌套必须走 forui 默认参数」的说法**过度归因**，新增抽屉不要因此回避嵌套。
10. 【**系统所有的弹出窗，都改为底层抽屉弹出**（强制条例，2026-09-10 用户拍板，全 App 适用）】**禁止**再新增任何居中弹窗（`showFDialog` / `FDialog` / `showDialog` / `AlertDialog` / `showCupertinoDialog`）；新增和改造**一律底部抽屉**：优先走模块内的封装入口（如 `todo_sheets.dart` 的 `_showTodoSheet`），裸调 `showFSheet<T>(context: context, side: FLayout.btt, mainAxisMaxRatio: AppTokens.sheetHeightLg, builder: (_) => SheetSurface(child: SafeArea(child: ...)))`。要点：① 内容必须用 `SheetSurface` 包底（forui 的 Sheet 链路不画 surface，直接给 Padding 会露出灰色 barrier「透明灰」实踩），它还统一提供 `Material` 祖先（抽屉内原生 `TextField` 必需）；② 需要结果时用泛型 + `Navigator.pop(c, true)`，`await showFSheet<bool>(...)` 正常拿到返回值，`showFDialog<bool>` 可原样平移；③ 按钮行建议两个 `Expanded` 并排（取消 outline / 确定 primary 或 destructive），比右对齐更贴移动端；④ 高度必须挂 **红线 #9 的三档之一**（`mainAxisMaxRatio` 传 0.8，禁止 `null` / 默认 9/16）；⑤ 表单状态（`current` 等）要提到 `StatefulBuilder` 之外的外层作用域，避免 setSt 重建被重置。**已全量改造完毕（2026-09-10）：全 App `showFDialog` 归零**，共 5 处居中弹窗改为抽屉——电子书 `features/ebook` 2 处（`_confirmRemove` 删除确认、`_editBookCategories` 分类选择）、`conversation_page.dart` 2 处（`_deleteTheme` 删除主题、`_confirmSoftDelete` 软删消息）、`notes/note_detail_page.dart` 1 处（`_delete`）；`epub_reader_page` 5 处与 file_vault / password_vault / file_transfer / todo / reminder 等模块本就是 `showFSheet`，仅同步修正注释里过时的「showFDialog / AlertDialog」字样。**其余任何模块都不得再新增居中弹窗**。

11. 【**Android 11+(API 30+) 写共享 Download 必须「所有文件访问」**】写系统 `Download/` 共享目录（电子书传书 `Download/渐离App传书`、文件互传 `Download/渐离App文件互传` 等）在 API 30+ **只有 `MANAGE_EXTERNAL_STORAGE`（「所有文件访问」）才有权限**，旧的 `READ/WRITE_EXTERNAL_STORAGE`(`Permission.storage`) 在 API 30+ 已**不再**授予写共享存储的权限。任何「判定可写共享 Download」的代码（`hasPublicDownloadsAccess` 之类）**绝不能**把 `Permission.storage.isGranted` 当成可写——否则 `createSync` 抛 `Permission denied` → 被 `catch` 静默回退到应用沙盒 → 文件管理器永远看不到。正确写法：`manageExternalStorage.isGranted` 为真即通过；否则仅当 `Build.VERSION.SDK_INT <= 29`（配合 manifest 的 `requestLegacyExternalStorage`）才允许 `Permission.storage`。落盘后务必 `MediaScannerConnection.scanFile` 让 MediaStore 索引（共享辅助见 `lib/core/android/media_scan.dart` + `MainActivity.kt` 的 `jianli/file_actions` 通道 `getSdkVersion`/`scanFile`）。`ferry_page.dart` 的权限判定仍是旧写法，新增写共享存储的代码照此修正。**2026-09-13 起：「公共 Download 子目录 + 权限 + 沙盒回退」已收口到共享 helper `lib/core/storage/public_downloads.dart`**（`hasPublicDownloadsAccess()` / `ensurePublicDownloadsPermission()` / `moduleDownloadDir(dirName)`）——新增写共享 Download 的模块**优先复用它**，别再各写一份；主题对话导出已用它落盘 `Download/渐离App导出/`（未授权回退沙盒 `Documents/渐离App导出/`）。文件互传 / 传书 / 隔空互传三处旧内联副本可后续迁移。**2026-09-13 起：「导出文本/Markdown 到 Download + 顶部提示」这一整条流程进一步收口到 `lib/app/ui/file_export.dart` 的 `exportTextToDownloadDir({context, text, filename, dirName=kExportDirName})`**（内含权限申请 → `moduleDownloadDir` → 写文件 → `scanFileInMediaStore` 索引 → `showFToast` 顶部提示 + `kExportDirName='渐离App导出'` + 同目录重名 ` (n)`）——新增「导出为 .md / 文本」的模块**直接调它**，别再内联这套流程；主题对话导出（单主题 + 批量）、笔记导出、习惯打卡导出、电子书导出已共用。⚠️ **可复用结论**：forui `showFToast` 经 `findAncestorStateOfType<FToasterState>()` 把条目挂到**根 FToaster**（与 Navigator 平级的 Stack），**不归 sheet 路由所有** → 抽屉内弹 toast 后再 `Navigator.pop` 不会把 toast 带走（「导出成功提示 → 关抽屉」顺序安全）。
12. 【**电子书传书 `importBookBytes` 不得因 contentHash 命中已有记录而跳过落盘**】跨端传书以内容 sha256 做身份键（对齐 PC `content_hash`），但**绝不能**在「命中已有 contentHash 记录」时直接 `return existing` 而不写文件——否则会出现「传书成功（书架能看）但系统文件管理器看不到」的诡异现象（2026-09-10 IV 实踩：从 PC 同步来的记录 / 旧沙盒路径已失效的记录会命中 hash → 函数早退、文件根本没落到 `Download/渐离App传书`）。正确做法（见 `features/ebook/repositories/ebook_repository.dart` 的 `importBookBytes`）：先按公开 `booksDir` 算出 `localPath`，**仅当** `existing != null && existing.filePath == localPath && File(existing.filePath).existsSync()` 时才复用不写；否则一律 `writeAsBytes` 落盘到 `localPath` 并 `scanFileInMediaStore(localPath)`，命中旧记录时**按 `content_hash` 去重删插**：删除所有同 `content_hash` 行 + 任何占用 `localPath` 的行，再 `insert` 一条规范行（保留 `percent`/`addedAt`）。⚠️ **严禁用可空 `id` 做 UPDATE**——`id` 为 NULL（沙盒/同步来的异常行）时会生成 `WHERE id IS NULL` 匹配不到、且同内容重复行会撞 `UNIQUE(file_path)` 抛 `SqliteException(1555)`（2026-09-10 VI 实踩）；一律按 `content_hash` 去重删插。书签/批注按 `content_hash` 关联，删行不影响。文件互传无此去重门故始终可见；电子书传书必须与其行为对齐，**不要「为了去重而牺牲系统可见性」**。

13. 【**列表页滚动吸顶以「搜索框」为锚点**（2026-09-12 用户拍板，全局强制）】列表页只要有页内搜索框，吸顶元素**只能是搜索行**——搜索框常驻视口顶部（滚动中随时可改关键词），横幅 / 条件 chip / **Tab 栏**都随滚动移出。❌ **不要**把锚点放在 Tab 栏（待办旧实现即「Tab 栏吸顶」，用户 2026-09-12 明确纠正）。实现要点：`SliverPersistentHeader(pinned: true)` + 自定义 delegate（模板 = `todo_page.dart` 的 `_PinnedHeader`，全 App 目前唯一先例，新增吸顶页照抄）；**吸顶高度必须由子节点用的同一批常量推导**（`_kSearchRowExtent = 上留白 + 框高 + 下留白`），且 `minExtent == maxExtent`，否则吸顶 / 松开瞬间会跳；吸顶行底色用 `AppTokens.pinnedCover(context, extent)`（背板同源渐变），**只在 `shrinkOffset > 0`（已滚动吸顶）时铺**、静止时透明透出背板（⚠️ 别直接刷 `colors.background` 纯色——静止时灰白挡板切断背景；`pageTint` 是透明色，用它会把内容透出来）。⚠️ **判断吸顶覆盖不能用 delegate 的 `overlapsContent` 参数**（pinned 头它恒 false——它是「前方是否有 floating sliver 压着自己」，本布局前方是 banner）**也不能给 `SliverPersistentHeader` 传 `overlapsContent:`（该 widget 无此命名参数，编译报错）**；正确信号是 `shrinkOffset > 0`。完整规格 + 踩坑表见 `modules/interaction-patterns.md` §4。

20. 【**送达走原生 `AlarmManager.setAlarmClock`（2026-09-16 修复「闹钟从未响」；2026-09-17 周期「通知」也改走原生）**】`delivery='alarm'` 的提醒**不再走 awesome_notifications 的 `preciseAlarm`**（它在 Android 12+ 未授权 `SCHEDULE_EXACT_ALARM` 会抛 `SecurityException` 且历史上未捕获 → 闹钟排程整体失败、从未响）。改走原生 **`AlarmManager.setAlarmClock`** —— 这是 Android 专门给「用户闹钟」的通路：**息屏 / Doze 下必响**、其 `showIntent` 在到点时带到前台。⚠️ **纠错（2026-09-18）**：此前本红线写「**不需要 `SCHEDULE_EXACT_ALARM` 权限**」是**错的**——官方文档把 `setAlarmClock()` 与 `setExact()`/`setExactAndAllowWhileIdle()` **并列为需要 `SCHEDULE_EXACT_ALARM` 的三个 API**（Android 12+ 未授予时抛 `SecurityException`；Android 13+ 新装默认**不预授予**）：<https://developer.android.com/about/versions/14/changes/schedule-exact-alarms>。故「走原生就一定响」不成立，**必须**配套 ①awesome 兜底 ②守护卡引导用户开「闹钟和提醒」；要让未授权时也拿到精确唤醒，唯一正解是声明 **`USE_EXACT_ALARM`**（安装即授予、用户不可撤销；代价 = 受 Google Play 政策限制，仅限闹钟/日历类核心功能，本项目暂未采用，见红线 #21）。链路：`reminder_repository.dart` 的 `_scheduleNativeAlarm`（时间模式 time/once/daily/weekly/monthly/yearly 计算下次触发）+ `_scheduleNativeInterval`（周期 `interval`：首次 `now+interval`、按 `repeatSpec` 的 `interval` 类型自排下次）→ `core/android/system_actions.dart` 的 `setAlarmClock(code, ..., mode)`/`cancelAlarmClock`/`cancelAlarmClocks`（MethodChannel `jianli/system_actions`）→ `AlarmScheduler.kt`。`setAlarmClock` 的 `mode` 决定响时行为：**`alarm`** = 构造指向全屏 `AlarmRingActivity` 的 `PendingIntent`（用户点「停止」时由 `AlarmScheduler.nextTrigger` 自排下次；「稍后提醒」= 5 分钟一次性）；**`notify`** = 构造指向广播 `ReminderAlarmReceiver` 的 `PendingIntent`（收到即发普通系统通知 + 自排下次，**无需用户操作**）。取消 = `cancelAlarmClock(code)`（同时按 alarm/notify 两种 `PendingIntent` 形态 cancel，保证都能命中）；`AlarmScheduler.cancel` 已内置双形态。`⚠️ 周期提醒（`mode='interval'`）无论「通知」还是「闹钟」送达**都走原生**：此前「周期 + 通知」走 awesome 的 `NotificationInterval`，在 Android 12+ 被 Doze/省电节流并自我停摆，表现为「只响 2 次就停 + 间隔不准」——已修复；**普通时间模式通知（daily/weekly/hourly… 非 interval）仍用 awesome**。`checkCapabilities()` 四项判定（红线 #16）与自愈重排/保活不变。新增闹钟相关能力只动原生 `AlarmScheduler.kt`/`AlarmRingActivity.kt`/`ReminderAlarmReceiver.kt`（新增）+ `system_actions.dart`，**不要回头用 awesome `preciseAlarm` 走闹钟**。

21. 【**原生通道传参铁律：数字一律按 `Number` 读 + 原生排程必须有 Dart 侧兜底（2026-09-18 修复「所有提醒都不生效」）**】① **Flutter `StandardMessageCodec` 把 int32 范围内的 Dart `int` 编成 Java `Integer`、超出才编成 `Long`**；Kotlin 侧若写死 `call.argument<Long>("x")`，收到 `Integer` 时在 checkcast 抛 **`ClassCastException`**。本项目致命案例：`SystemActionsChannel.kt` 的 `setAlarmClock` 读 `argument<Long>("intervalMillis")`，而 `system_actions.dart` **每次调用都会带 `intervalMillis`（默认 `0` 也是 int32）** → **每一次 `setAlarmClock` 都抛异常** → 被外层 `catch (e: Exception) { result.success(false) }` 吞掉 → 原生闹钟与周期提醒**永远排不上、且无任何日志**。**铁律：原生通道读数字参数一律 `call.argument<Number>("x")?.toLong()` / `?.toInt()`**（`Number` 兼容 `Integer`/`Long`）；`catch` 里**必须 `Log.e(...)`**，否则静默失效无从定位。② **原生排程失败必须回退 awesome，否则「先取消再重排」= 永久静默**：`rescheduleAll()`/`saveReminder()` 都是「先 `_cancelAllSchedules` 再 `scheduleNotification`」，一旦原生桥返回 false（通道异常 / 机型限制 / **未授予 `SCHEDULE_EXACT_ALARM`，见红线 #20**）而 Dart 侧不兜底，提醒就被取消后再也排不上 → 表现为「**所有提醒都不响，连 App 页面内也不弹**」。故 `scheduleNotification` 三条分支**必须**写成 `if (await _scheduleNativeXxx(item)) return; await _scheduleAwesomeXxx(item);`——`_scheduleNativeAlarm`/`_scheduleNativeInterval` 统一返回 **`Future<bool>`**（true = 原生桥已接手），false 时由 `_scheduleAwesomeTime(fullScreen: true)` / `_scheduleAwesomeInterval` 兜底（awesome 的 `preciseAlarm` 在权限缺失时自动降级为不精确，**保证一定排得上**）。⚠️ 兜底路径的 `precise`/`fullScreen` 一律传 `fullScreen` 形参（**含 weekly 分支，别写死 `false`**）——否则闹钟送达回退后只弹横幅、不锁屏全屏。③ **排查口诀**：「提醒完全不响」先 `adb logcat | grep SystemActionsChannel`，出现 `method setAlarmClock failed` 即本红线；再查守护卡「闹钟和提醒」是否已授权。

22. 【**通知渠道重要性 = 悬浮横幅的唯一开关；改重要性只能换渠道键（2026-09-18，用户要求「所有提醒像倒计时一样在屏幕上直接看到」）**】① **要在屏幕上方直接弹出（悬浮横幅 / heads-up，不用下拉通知栏），渠道重要性必须是 `NotificationImportance.High`**——awesome 官方枚举注释写得很直白：`Default` = "shows everywhere, makes noise, but **does not visually intrude**"，`High` = "makes noise and **peeks**"。历史上只有 `countdown` / `alarm` 是 `High`，而 `habit` / `todo` / `pomodoro` 没写 `importance`（= Default）⇒ **只有倒计时会弹横幅，其余静默进通知栏**。2026-09-18 已把 5 个渠道统一为 `High` + `enableVibration: true` + `defaultPrivacy: NotificationPrivacy.Public`（锁屏完整可见）。⚠️ **新增任何通知渠道一律显式写 `importance: NotificationImportance.High`**，省了就退回「静默进通知栏」。② **Android 渠道一经创建即永久锁定**：同名再 `createNotificationChannel` 是 no-op（新重要性被忽略）；「先删除再重建同名」也不行——删除是**软删除**，系统会记住该键并把**旧设置复活**给重建的渠道（防 App 绕过用户选择）。⇒ **唯一能改重要性的办法是换一个新的渠道键**。本项目做法（`notification_service.dart`）：键名加版本后缀（`habit`→`habit_v2`、`todo`→`todo_v2`、`pomodoro`→`pomodoro_v2`，未改重要性的 `countdown`/`alarm` 保持原键不动），旧键登记进 `NotificationChannels.legacyKeys` 并由 `NotificationService.init()` 在 `initialize()` **之后**逐个 `removeChannel` 删除（**顺序不能反**，反了会被 initialize 重新创建回来）；历史通知 payload 里残留的旧键由 `NotificationChannels.legacyKeyMap` + `NotificationService.migrateChannelKey()` 在 `_onActionReceived`（贪睡重排）时迁移。**下次再改重要性请继续换键（`_v3`）**。③ **原生侧的周期「通知」渠道**（`AlarmScheduler.NOTIFY_CHANNEL_ID = "reminder_notify"`）建渠道时就是 `IMPORTANCE_HIGH`，**无需换键**；其 `postNotification` 已带 `setPriority(PRIORITY_HIGH)` + `setCategory(CATEGORY_REMINDER)` + `setVisibility(VISIBILITY_PUBLIC)`。④ **改完渠道设置必须让提醒重新排程**（否则已排的计划仍挂在旧渠道上）——`rescheduleAll()` 在冷启动/回前台会自动跑，无需额外操作。⑤ **厂商 ROM（小米/华为/OPPO/vivo）另有独立的「悬浮通知 / 锁屏显示 / 横幅」开关，App 无法代开**，只能在「提醒守护」抽屉里引导用户去系统设置；**不要承诺「一定能弹横幅」**。
